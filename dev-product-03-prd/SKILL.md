# 产品-03: PRD编写

基于需求分析、头脑风暴和原型设计，编写完整的产品需求文档，包含系统页面截图。

## 触发条件

- 需求和原型已确认，需要输出正式的产品需求文档
- 用户提到 "PRD"、"产品需求文档"、"写需求文档"
- 需要给设计和开发团队提供正式的需求基线

## 执行步骤

### Step 1: 文档框架搭建

创建 PRD 文档的基本框架。

### Step 2: 产品概述

包含产品愿景、产品定位、目标用户画像、核心价值主张。

### Step 3: 功能需求详述

为每个功能模块编写详细说明，**必须附带对应页面截图**：

```markdown
## 功能模块: [模块名称]

### 用户故事
作为 [角色]，我想要 [功能]，以便 [价值]。

### 功能描述
[详细描述这个功能做什么]

### 页面截图
![页面名称](截图路径)

### 详细规则
| 规则编号 | 规则描述 | 备注 |
|---------|---------|------|
| R-001 | | |

### 边界条件
- 当 [条件] 时，系统应 [行为]

### 异常处理
| 异常场景 | 系统行为 | 用户提示 |
|---------|---------|---------|
| | | |
```

### Step 4: 非功能需求

包含性能要求、安全要求、兼容性要求。

### Step 5: 里程碑与验收

包含阶段划分、关键时间节点、验收标准。

### Step 6: 评审确认

1. 技术团队评审 — 确认技术可行性
2. 设计团队评审 — 确认设计可实现性
3. 业务方评审 — 确认需求完整性
4. 签字确认 — 形成需求基线

## 页面截图规范

- **来源**：从原型 Demo 中截取
- **范围**：每个功能模块至少 1 张完整页面截图
- **标注**：关键交互区域用红框标注并编号说明
- **状态**：核心页面需包含正常状态和空状态截图
- **格式**：PNG 格式，分辨率 1440px 宽度
- **命名**：`模块名-页面名-状态.png`

## 输出物

- 完整的 PRD 文档（含页面截图）
- 功能需求清单（含优先级）
- 非功能需求指标
- 里程碑计划
- 验收标准
- 页面截图集

## 质量检查清单

- [ ] 所有 P0 功能有用户故事和详细规则
- [ ] 每个功能模块有对应页面截图
- [ ] 截图标注清晰，关键区域已标注
- [ ] 边界条件和异常处理已覆盖
- [ ] 非功能需求有量化指标
- [ ] 验收标准可量化、可验证
- [ ] 技术团队已确认可行性
- [ ] 利益相关者已签字确认
