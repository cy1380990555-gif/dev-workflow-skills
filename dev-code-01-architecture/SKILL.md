# 开发-01: 技术架构设计

基于 PRD、价值文档和 UI 设计，设计系统的技术架构，包括技术选型、API 设计、数据模型和部署方案。

## 触发条件

- PRD、价值文档和 UI 设计已完成，需要设计技术方案
- 用户提到 "技术架构"、"架构设计"、"系统设计"、"技术选型"
- 开发团队需要技术方案才能开始编码

## 执行步骤

### Step 1: 架构概述

包含系统定位、设计原则、架构风格。

```markdown
## 架构概述

### 设计原则
| 原则 | 说明 |
|------|------|
| 简单优先 | 优先选择简单方案，避免过度设计 |
| 渐进演进 | 架构支持后续扩展，但不提前实现 |
| 高内聚低耦合 | 模块职责清晰，依赖方向合理 |
| 失败隔离 | 单点故障不影响全局 |
```

### Step 2: 技术选型

```markdown
## 技术选型

### 前端
| 选项 | 框架 | 状态管理 | UI库 | 构建工具 |
|------|------|---------|------|---------|
| **选择** | | | | |

### 后端
| 选项 | 语言 | 框架 | ORM | |
|------|------|------|-----|---|
| **选择** | | | | |

### 数据层
| 组件 | 选择 | 理由 |
|------|------|------|
| 主数据库 | | |
| 缓存 | | |
| 消息队列 | | |
```

### Step 3: 系统架构图

描述系统拓扑、服务依赖关系、数据流向。

### Step 4: API 契约定义

```markdown
## API 契约

### 接口规范
- 基础路径: `/api/v1`
- 认证方式: [JWT / OAuth2 / API Key]

### 接口清单
| 方法 | 路径 | 说明 | 认证 | 限流 |
|------|------|------|------|------|
| POST | /api/v1/xxx | 创建 | 否 | 10/min |
| GET | /api/v1/xxx | 查询 | 是 | 100/min |
```

### Step 5: 数据模型设计

包含 ER 关系、表结构、索引策略、数据迁移方案。

### Step 6: 非功能性设计

包含高可用、性能、安全、可观测性设计。

### Step 7: 部署架构

包含环境规划、CI/CD 流水线、容量规划。

## 输出物

- 架构概述文档
- 技术选型对比和决策
- 系统架构图
- API 契约文档
- 数据模型设计
- 非功能性设计方案
- 部署架构方案

## 质量检查清单

- [ ] 技术选型有对比和理由
- [ ] 系统架构图清晰完整
- [ ] API 契约覆盖所有 P0 功能
- [ ] 数据模型满足业务需求
- [ ] 非功能需求有具体方案
- [ ] 部署方案可执行
- [ ] 团队已评审确认
