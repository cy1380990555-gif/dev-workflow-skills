# 开发-03: 代码审查

审查代码质量、安全性、性能和架构合规性，确保代码符合标准。

## 触发条件

- 代码编写完成，需要审查后合并
- 用户提到 "代码审查"、"代码评审"、"CR"、"Code Review"
- 合并请求/PR 提交后

## 执行步骤

### Step 1: 自动化检查

```markdown
## 自动化检查

### 静态分析
- [ ] Lint 检查通过（无 error，warning ≤ 5）
- [ ] 格式化检查通过
- [ ] 类型检查通过（TypeScript 项目）
- [ ] 依赖安全扫描无高危漏洞

### 测试
- [ ] 单元测试全部通过
- [ ] 核心逻辑覆盖率 ≥ 80%

### 构建
- [ ] 项目可成功构建
```

### Step 2: 代码质量审查

检查可读性、可维护性、错误处理。

### Step 3: 安全审查

检查输入处理、认证授权、数据安全。

### Step 4: 性能审查

检查 N+1 查询、缓存使用、分页处理。

### Step 5: 架构合规审查

检查分层、依赖方向、API 契约一致性。

### Step 6: 输出审查报告

```markdown
## 代码审查报告

### 审查概要
| 项目 | 内容 |
|------|------|
| 审查范围 | [文件/模块列表] |
| 审查结论 | [通过 / 有条件通过 / 不通过] |
| 🔴 阻塞问题 | X个 |
| 🟡 重要问题 | X个 |
| 🔵 建议改进 | X个 |
```

## 审查结论规则

| 结论 | 条件 | 后续 |
|------|------|------|
| **通过** | 无🔴，🟡≤3 | → 进入系统测试 |
| **有条件通过** | 无🔴，🟡>3 | → 修复🟡后进入系统测试 |
| **不通过** | 有🔴 | → 返回代码编写，修复后重新审查 |

## 输出物

- 代码审查报告
- 问题清单（按严重程度分类）
- 修复建议

## 质量检查清单

- [ ] 自动化检查全部通过
- [ ] 代码质量审查完成
- [ ] 安全审查完成
- [ ] 性能审查完成
- [ ] 架构合规审查完成
- [ ] 审查结论已明确

## 交接条件

- **通过** → **系统测试** (dev-test-02-testing)
- **有条件通过** → 修复后 → **系统测试** (dev-test-02-testing)
- **不通过** → 返回 **代码编写** (dev-code-02-coding)
