# 开发-02: 代码编写

基于 PRD、架构设计和 UI 设计，实现软件代码。

## 触发条件

- 技术架构设计已完成，可以开始编码
- 用户提到 "代码编写"、"编码"、"开发"、"写代码"、"实现功能"
- 需要将设计转化为可运行的代码

## 执行步骤

### Step 1: 工程初始化

```markdown
## 工程初始化检查清单

### 基础配置
- [ ] 依赖管理文件（package.json / go.mod / pom.xml）
- [ ] 构建配置（webpack / vite / maven / gradle）
- [ ] 代码格式化配置（prettier / eslint / checkstyle）
- [ ] Git 配置（.gitignore / commitlint）
- [ ] 环境配置模板（.env.example）
```

### Step 2: 基础设施代码

按优先级实现：数据库连接和配置 → 中间件 → 工具类 → 基础前端框架。

### Step 3: 按优先级实现功能

```markdown
## 功能实现计划

### P0 功能（必须实现）
| 功能 | 涉及模块 | 预计复杂度 | 状态 |
|------|---------|-----------|------|
| | 前端+后端 | 高/中/低 | 待开发 |

### 实现顺序原则
1. 先后端接口，后前端页面
2. 先核心流程，后边缘场景
3. 先数据写入，后数据查询
4. 先实现功能，后优化性能
```

### Step 4: 单元测试

```markdown
## 单元测试要求

### 覆盖范围
| 层级 | 最低覆盖率 | 重点测试 |
|------|-----------|---------|
| 业务逻辑层 | 80% | 核心规则、边界条件 |
| 数据访问层 | 60% | CRUD、复杂查询 |
| 工具类 | 90% | 边界值、异常输入 |
```

### Step 5: 自测验证

- [ ] P0 功能可正常运行
- [ ] 正常流程走通
- [ ] 异常场景有合理提示
- [ ] 边界条件处理正确
- [ ] 代码可编译/构建通过
- [ ] Lint 检查通过

## 编码原则

1. 遵循项目编码规范
2. 优先实现 P0 功能
3. 保持代码简洁，避免过度设计
4. 关键逻辑写测试
5. 提交规范：Conventional Commits

## 输出物

- 项目工程代码
- 数据库迁移脚本
- 单元测试代码
- 接口文档
- 环境配置模板

## 质量检查清单

- [ ] P0 功能代码已完成
- [ ] 代码可编译/构建通过
- [ ] 单元测试通过（核心逻辑覆盖率 ≥ 80%）
- [ ] Lint 检查通过
- [ ] 开发自测通过
- [ ] 无硬编码密钥和敏感信息
