# 产品-01: 需求分析

将原始的用户需求、业务背景和利益相关者输入，转化为结构化的需求文档。

## 触发条件

- 项目启动，收到原始需求
- 用户提到 "需求分析"、"需求梳理"、"整理需求"
- 从零开始的新功能/新项目

## 执行步骤

### Step 1: 需求收集

向用户提出以下问题（按需选取）：

**业务背景类**
- 这个项目要解决什么业务问题？
- 目标用户是谁？有多少人使用？
- 现在是怎么做的？有什么痛点？

**功能范围类**
- 核心功能有哪些？（请列举 3-5 个最重要的）
- 有没有参考产品或竞品？
- 哪些功能是必须有的，哪些是锦上添花？

**约束条件类**
- 有没有时间要求？什么时候需要上线？
- 有没有技术限制？（如必须用某个技术栈）
- 预算和团队情况如何？

**质量期望类**
- 对性能有什么要求？（响应时间、并发量）
- 对安全有什么要求？
- 需要支持哪些平台/浏览器？

### Step 2: 需求整理

将收集到的信息按以下模板整理：

```markdown
# 需求分析文档

## 1. 项目概述
- **项目名称**：
- **项目背景**：
- **业务目标**：
- **目标用户**：

## 2. 业务流程

### 核心业务流程
[用文字描述当前业务是如何运作的，从起点到终点的完整链路]

### 业务流程痛点
| 流程环节 | 当前痛点 | 影响范围 | 期望改善 |
|---------|---------|---------|---------|
| | | | |

## 3. 业务场景

### 场景1: [场景名称]
- **角色**: [谁在什么场景下做什么]
- **触发条件**: [什么情况下会进入这个场景]
- **当前做法**: [现在是怎么处理的]
- **期望做法**: [上线后希望怎么处理]
- **业务价值**: [改善后带来什么价值]

## 4. 功能需求

| 编号 | 功能名称 | 功能描述 | 优先级 |
|------|---------|---------|--------|
| F-001 | | | P0 |
| F-002 | | | P0 |
| F-003 | | | P1 |

**优先级说明**:
- P0: 必须有（Must Have）— 没有这个功能系统无法运行
- P1: 应该有（Should Have）— 重要但非阻断性功能
- P2: 可以有（Could Have）— 锦上添花的功能

## 5. 非功能需求
- **性能**：
- **安全**：
- **可用性**：
- **兼容性**：

## 6. 约束与假设
- **技术约束**：
- **时间约束**：
- **资源约束**：
- **假设条件**：

## 7. 不在范围内（Won't Have）
- 明确列出本次不做的事项
```

### Step 3: 需求验证

与用户逐项确认业务流程、业务场景、需求完整性、优先级、约束假设和范围边界。

### Step 4: 需求确认

获得用户明确确认后，输出最终需求文档。

## 输出物

- 结构化需求文档（上述模板，含业务流程、业务场景、功能清单）
- 功能需求清单（编号/名称/描述/优先级）
- 待澄清问题清单（如有）

## 质量检查清单

- [ ] 业务流程已梳理，痛点已识别
- [ ] 业务场景已覆盖核心角色和场景
- [ ] 功能需求按编号/名称/描述/优先级罗列
- [ ] 所有 P0 功能描述清晰无歧义
- [ ] 需求之间无矛盾
- [ ] 优先级排序有业务依据
- [ ] 非功能需求有量化指标
- [ ] "不在范围内" 已明确
- [ ] 用户已确认
