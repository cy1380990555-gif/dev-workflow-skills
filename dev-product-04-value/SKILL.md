# 产品-04: 价值编写

基于功能清单，梳理每个功能帮助业务增收、提效的价值，计算出具体数值，给出计算逻辑公式。

## 触发条件

- PRD 已完成，需要量化功能价值
- 用户提到 "价值编写"、"商业价值"、"ROI"、"增收降本"
- 需要向管理层申请项目预算或审批

## 核心原则

- **基于功能清单**：逐个功能分析价值，不凭空编造
- **只写增收和提效**：增收 = 帮业务多赚钱；提效 = 帮业务省时间/省成本
- **必须有具体数值**：不能只写"提升效率"，要写"每月节省 120 人时，折合 ¥18,000"
- **必须有计算公式**：每个数值都要有推导逻辑，让人能验算
- **纯文字即可**：不需要图表，用清晰的文字+公式+数字表达

## 执行步骤

### Step 1: 功能价值梳理

从需求分析的功能清单出发，逐个分析每个功能的价值：

```markdown
| 编号 | 功能名称 | 价值类型 | 价值描述 | 是否可量化 |
|------|---------|---------|---------|-----------|
| F-001 | | 增收/提效/无直接价值 | | 是/否 |

> 价值类型说明：
> - 增收：直接或间接带来收入增长
> - 提效：减少人工操作、缩短流程时间、降低出错率
> - 无直接价值：基础设施类功能（如登录、权限），不单独量化
```

### Step 2: 增收价值计算

为每个增收功能写出计算公式和具体数值：

```markdown
## 增收价值

### F-XXX: [功能名称]

**增收逻辑**：
[用一段话说明这个功能如何带来收入增长]

**计算公式**：
月增收金额 = [参数A] × [参数B] × [参数C]

**参数取值**：
- 参数A（[参数名称]）：[数值] [单位]，来源：[数据来源]
- 参数B（[参数名称]）：[数值] [单位]，来源：[数据来源]
- 参数C（[参数名称]）：[数值] [单位]，来源：[数据来源]

**计算过程**：
月增收 = [A值] × [B值] × [C值] = ¥[具体数值]/月
年增收 = ¥[具体数值] × 12 = ¥[具体数值]/年
```

### Step 3: 提效价值计算

为每个提效功能写出计算公式和具体数值：

```markdown
## 提效价值

### F-XXX: [功能名称]

**提效逻辑**：
[用一段话说明这个功能如何提升效率]

**计算公式**：
月节省成本 = [参数A] × [参数B] × [参数C]

**参数取值**：
- 参数A（[参数名称]）：[数值] [单位]，来源：[数据来源]
- 参数B（[参数名称]）：[数值] [单位]，来源：[数据来源]
- 参数C（[参数名称]）：[数值] [单位]，来源：[数据来源]

**计算过程**：
月节省人时 = [A值] × [B值] × [C值] = X 人时/月
月节省成本 = X × ¥[人时成本] = ¥[具体数值]/月
年节省成本 = ¥[具体数值] × 12 = ¥[具体数值]/年
```

### Step 4: 价值汇总

```markdown
## 价值汇总

### 增收价值汇总
| 功能编号 | 功能名称 | 月增收 | 年增收 |
|---------|---------|--------|--------|
| **合计** | | **¥** | **¥** |

### 提效价值汇总
| 功能编号 | 功能名称 | 月节省人时 | 月节省成本 | 年节省成本 |
|---------|---------|-----------|-----------|-----------|
| **合计** | | | **¥** | **¥** |

### 总价值
| 指标 | 月度 | 年度 |

| 增收 | ¥ | ¥ |
| 提效（节省成本） | ¥ | ¥ |
| **合计** | **¥** | **¥** |
```

### Step 5: 价值假设说明

```markdown
## 价值假设说明

以上计算基于以下假设，如假设不成立则需调整：
1. [假设1]：[说明]，依据：[来源]
2. [假设2]：[说明]，依据：[来源]
```

## 输出物

- 功能价值梳理表（每个功能的增收/提效分类）
- 增收价值计算（含公式、参数、计算过程、具体数值）
- 提效价值计算（含公式、参数、计算过程、具体数值）
- 价值汇总表
- 价值假设说明
